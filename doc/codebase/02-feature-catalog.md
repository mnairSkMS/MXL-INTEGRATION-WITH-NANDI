# Feature Catalog

This catalog lists capabilities reachable from the production build graph. It is a navigation and evidence guide, not a promise that every codec/protocol combination works. Status labels follow [scope and evidence](00-scope-and-evidence.md); configuration details are in [05](05-configuration-reference.md) and the complete control-plane contract is in [17](17-rest-grpc-and-sqlite-control-plane.md).

| SRT input | `srt://`; SRT parameters | `SingleInput`, `srtsrc` | Runtime verified | Caller/listener, latency, and buffer size; SRT bypasses the generic 3 s live prefill and retains bounded source/per-stream queues. | Playlist input | `pls+file://` URI; managed snapshots | `PlaylistInput`, `playlist::Parser`, `applyPlaylistSnapshot` | Runtime verified | The 1920×1080/25 fps loop accepts stable-ID three-item snapshots while on air; insert, reorder and removal of a queued/preloaded item are applied asynchronously. | Playlist/manual switching | REST or gRPC input API; `UTPL_PLAYLIST_MAKE_BEFORE_BREAK=0` disables make-before-break | `setCurrentStream`, `LiveTimeline`, `_armPending`/`_cutOver`/`_abortArm` in `playlist.cpp` | Runtime verified | REST switching changed both `currentStreamId` and decoded output; the POST response can precede the asynchronous state change. A forced switch with an item on air is make-before-break: the next item decodes while the current one stays on air, and the cut keeps the live item at its arrival latency (SRT ↔ MXF: 3-4 repeated frames file → live, one live → file). A live item plays its frames as they leave the decoder plus `UTPL_PLAYLIST_LIVE_MARGIN_MS` (80 ms) instead of waiting out the source's mux delay: after a return to live the SRT test output trails the source by 0.41 s instead of 0.86 s. | Redundant live input | Two URIs in `inputs[0].transport.uri` | `StandardInput`, selectors/fallback | Integration gated | Requires `fallbackswitch`; failover/failback timing not runtime proven. |
| NDI input | `ndi://`, `transport.ndi` | `SingleInput`, `ndisrc` | Integration gated | Requires NDI SDK/plugin and licensed environment. |
| MXL source tap (copy of the decoded input into MXL flows) | `inputs[n].mxlTap` | `MxlTap` (`mxltap.cpp`), `MxlFrameGrid`, `BaseInputStream::linkSrcPad`, parser `mxlTap` block | Runtime verified (14 tests) | Video v210 at the source size/rate, first audio stream as Float32 48 kHz, 1–8 channels. | MXL programme output (the finished programme written to MXL flows) | `outputs[n]` with `"type": "mxl"` and an `mxl` block | `MxlOutput` (`output/mxl.cpp`), `MxlFlowline` (`channel/processor/transcoder/mxlflowline.cpp`), `Codec::MXL`, `OutputType::MXL`, parser `mxl` output branch | Runtime verified (6 tests) | The processors' raw picture (BGRA canvas, converted to v210 in a side pipeline) and processed audio (Float32 48 kHz, 1–8 channels), with a size and rate of its own. Shares a processor with an on-air output of the same size and rate. Fail-open. See 41 and 05. |
| MXL input (MXL flows read into a channel) | `mxl:///<domain>` uri with `transport.mxl.{video,audio}.flowId`; channel form "MXL flows" | `SingleInput::_createMxlFlows` (`input/single.cpp`: `mxlsrc` per flow, leaky queue, v210 → I420, `audiobuffersplit`, watchdog, shared time shift), `MxlInputTransportParameters`, `Protocol::MXL`, parser `_parseMxlInput` | Runtime verified (10 tests, scratch build) | Waits for flows that are not there yet, reattaches a flow with no data for 3 s, not prebuffered. No passthrough, SCTE-35, interlaced, data flow, second audio flow, redundant or playlist MXL input. Dolby paths **integration gated**. See [05](05-configuration-reference.md#input-mxl) and [41](41-mxl-integration.md#mxl-input-step-4). |
| RTMP input (push via bundled relay, pull) | `rtmp://`, `rtmps://`; channel form "RTMP / RTMPS" | `SingleInput` RTMP branch (`rtmp2src`, FLV→TS remux), MediaMTX `rtmp_relay` | Runtime verified (push and external pull, `rtmp://`) | Engine-first and encoder-first start; recovers from abrupt drops, clean unpublishes and 70 s outages within about 8 s; output decodes cleanly with A/V within 15 ms per segment and carries the source picture on HLS and SRT. H.264 + AAC/MP3 only. RTMPS shares the code path but is integration gated. See 07. |
| Setup-time input probe | `GET /inputs/probe` | `services/probe.py`, `ffprobe` | Runtime verified | Reports codec, resolution, frame rate, scan type, audio tracks and MPEG-TS PIDs. | Dynamic stream discovery | automatic | `decodebin`, pad/caps callbacks | Statically implemented | Actual decoders/demuxers come from installed registry. |

## Unsupported or not exposed as a stable contract

- More than one independent configured input/channel in a process; only the first input object is parsed.
- Playlist plus codec passthrough, redundant file/playlist input, or HLS output with passthrough video.
- Generic caption transcoding or JSON-configured caption output streams.
- Arbitrary group protocols or nested group links; group delivery is single-transport HLS/HTTP only.
- Configurable SCTE event preroll: the schema field is not parsed and the 4000 ms class default remains.
- Adobe/enhanced HLS SCTE markers; their parser branches are compiled out.
- ESAM `SCTE35PointDescriptor`.
- Any GPU, NDI, S3, external encoder, license server, POIS server, or network-peer combination that has not been run in the target environment; these are integration gated.
- A flow registry and MXL Fabrics **in the transcoder**. Neither is implemented; they are planned and integration gated. The source tap (`inputs[n].mxlTap`), the programme output (`outputs[n].type = "mxl"`) and the MXL input (`mxl:///` uri) are implemented; the MXL plugin and tools are in the images and runtime verified by the SDK tests. See [41](41-mxl-integration.md).

Add or update a row whenever production behavior changes, and link the runtime/build evidence in the owning subsystem page.
