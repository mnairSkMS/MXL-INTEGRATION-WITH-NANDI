## MXL input findings (2026-11-05)

Details in [41](41-mxl-integration.md#mxl-input-step-4).

- **P2 (fixed in our images by a patch, worked around in the engine as well): `mxlsrc` can deadlock a channel whose pads are blocked until it plays.** It holds its state lock while it pushes its caps downstream; the change to playing asks it for its latency, which needs the lock. `transcoder/patches/mxl/010-mxlsrc-release-locks-before-set-caps.patch` releases the locks before the push (shown by a scratch build without the engine's measures: stock plugin hangs, patched plugin runs). The engine keeps its leaky queue and dropped ALLOCATION query so a stock plugin still works. Not reported to the MXL project yet.
- **P2 (handled in the engine): a reader never notices a new writer.** Same as the Phase 1 finding, now covered by the input's 3 s no-data reattach (test `03`).
- **P3 (open, intermittent): one silent failure of `input/11-delay` on 2026-11-05.** The test captures channel B's output with `ffmpeg`; under `bash -e` a failed capture ends the script without a message, which is what the first full run showed. It passed in the 8 runs after, and the test now reports a failed capture with B's log tail. Cause unknown; a startup hang of channel B is the case to rule out if it returns. Related: the writer-restart recovery of `input/03` was 5.3 s in four runs and 15.8 s in one.
- **P3 (measured, open): the delay of an MXL input** (`transport.mxl.delayMs`, default 500 ms) has to cover the movement of the writer's lag plus a constant 160 to 180 ms between a Nandi programme output's picture and its sound. The default is 140 ms above the worst spread measured (358 ms, every core busy). It is not measured against any limit (Gate A not agreed). Learning the constant difference (waiting for the first buffer of every flow) would cut the needed delay to about 100 ms; not built. See [41](41-mxl-integration.md#the-delay-of-an-mxl-input).
- **P3 (UI): the built channel UI under `api/src/transcoder_api/static/channel/` was not rebuilt** for the MXL input (nor for the earlier programme-output keep-through). The sources in `frontend/` and their tests are current.
- **P3: an MXL input cannot be probed** (`GET /inputs/probe` answers 422 for transport `mxl`; the API image has no MXL tools).
- **P3: `mxl_write_video` in the test framework needs a fraction for the frame rate** (`25/1`); `25` produces invalid caps and a writer that dies silently.
